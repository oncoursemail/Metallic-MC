# Metallic MC — social world and minigame product research

**Date:** 2026-10-18 · **Status:** experience blueprint, not implemented. This is a first-party original game network. Do not reuse Mineclub art/code/brand or claim its fan wiki is authoritative about every historical feature.

## Metallic's original experience architecture

### 1. The Districts — social persistent spaces
- Own a small personal home then collaborate on a friends-only District. Persistent spaces have quotas, backups, access roles, audit trails and safe recovery.
- In-world build mode with custom block display models, furniture snap/rotate, palette variants and real-time co-editing. Use original Blockbench models and versioned resource packs; never require a client mod to join.
- Java/Bedrock validation matrix: geometry/animation limitations, controller/touch navigation, resource pack download consent, camera and chat moderation. Not every feature can be identical on both clients.

### 2. Arcade — original minigame fleet
- Repeatable, distinctive modes (party platformers, cooperative logic arenas, capture games, traversal races) built for reliable p95/p99 tick timings, not just a giant list of untested games.
- Match Director: fair matchmaking, parties and groups, spectator mode, reconnect window, opt-in cross-region play, tiered ready-instance buffer.
- Game logic plugin SDK using Paper for standard compatibility; independent Minestom modes when custom mechanics do not need vanilla features. Folia requires actual special compatibility work.

### 3. The Workshop — safe creator ecosystem
- Creator-controlled private staging rooms and guided visual editors; server-side published assets built from Blockbench-compatible formats, licensed textures/audio and versioned templates.
- UGC verification: model triangle/texture budgets, security scans, moderation review, safe asset sandbox, copyright attribution, content appeal process and rollback.
- Set per-world entity/block/chunk budgets tied to measurable performance costs. Player-created content must not increase p99 MSPT for unrelated rooms.

### 4. Identity, cosmetics and social UI
- Consistent player identity, cosmetics previews, outfits, effects, emoting, achievements, friends/party system and moderated chat. Controller/touch UI must be designed deliberately rather than ported Java inventory controls blindly.
- Transparent shops and original cosmetic art, no advantage-granting purchases or deceptive rewards; check Minecraft Usage Guidelines, consumer law, minors' privacy and platform monetization rules before launch.
- An original menu/art direction that complements Metallic branding and does not appear autogenerated; dedicated illustration, 3D modelling, animation and UI design critiques.

### 5. Star AI in the social world
- Consentful NPC guides, creator assistants, event narrators, translation or accessibility assistance. All prompts go through a budgeted asynchronous AI gateway, not directly from the game tick loop.
- Bounded token budgets, per-player queues and global concurrency, moderation, fallback scripted dialogue, data retention limits, protected admin permission separation.
- Star AI can help make *proposals* for plugins and art, but never publish unreviewed live code or bypass anti-abuse safeguards.

## The release order

0. **Prove the foundations.** Protected Java/Bedrock connection, world backups, safe plugin boundaries, dedicated management and first-player tests.
1. **One excellent social lobby + one polished game.** Better to ship a game that stays at tick SLO under realistic load than twelve half-working modes.
2. **Housing alpha.** Land permissions, decorations, editable furniture, world restore, resource pack quality and Bedrock input parity.
3. **Persistent network identity.** Parties, presence, friends, achievements, moderation and cosmetics catalogue.
4. **Creator Workshop.** Staging worlds and performance quotas; creator asset approvals, versioning, content scanning and sharing.
5. **AI NPC beta.** Bounded, age-appropriate assistive interactions with human override and fixed costs, then experiment with genuinely novel gameplay.

## What would make it better — falsifiable goals

- Faster queue-to-play (p95) from warmed instances; visible player transfer reliability for Bedrock and Java.
- Multiplayer social worlds that don't stall neighboring games when one world is busy; per-world resource limits.
- Creator economy transparent and safe, including moderation/appeals and performance controls.
- Accessible motion and clear interaction design, especially mobile/controller players.
- Factual monitoring of gameplay latency, crash recovery, worlds restored, patch rollout and quality regressions.

No comparative "best-ever" claim should be published without user research, measured benchmarks and direct feature tests against current alternatives.
